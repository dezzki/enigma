# 8. References

The references below are grouped by kind and numbered in IEEE style. Project documents are listed first because they are the primary sources for requirements, scenarios, and process; external platforms follow because they informed the competitive landscape and gamification design; standards and legal instruments follow; and software engineering theory closes the list. All external sources are real, publicly identifiable works, and the URLs are the canonical locations of the cited material.

1. V. Garg, N. V. Biswas, S. Maurya, and S. Arora, "Enigma — Product Requirements Document," Software Engineering Semester 5, Keshav Mahavidyalaya, University of Delhi, 2026. [Online]. Available: `Enigma.md`, `Enigma-PRD.md`. Primary source for the vision, personas, functional requirements, KPIs, and the five end-to-end scenarios replayed in §7.4.
2. V. Garg, N. V. Biswas, S. Maurya, and S. Arora, "Enigma — Software Requirement Specification," Software Engineering Semester 5, Keshav Mahavidyalaya, University of Delhi, 2026. [Online]. Available: `Enigma-SRS.md`. Source for the numbered FR-1 to FR-10 requirements, performance budgets, design constraints, and data dictionary used as test oracles.
3. V. Garg, N. V. Biswas, S. Maurya, and S. Arora, "Enigma — Iterative Process Flow Breakdown," Software Engineering Semester 5, Keshav Mahavidyalaya, University of Delhi, 2026. [Online]. Available: `process-flow.md`. Describes the Communication, Planning, Modeling, and Construction loop and the iteration gates that shape the test schedule.
4. Department of Computer Science, "SE Report Template," Keshav Mahavidyalaya, University of Delhi. [Online]. Available: `SE Report Template.docx`. Prescribed structure and formatting conventions followed by this report.
5. Habitica, "Habitica — Gamified Habit and Task Tracking." [Online]. Available: https://habitica.com/. Reference for RPG-style XP, levels, and reward mechanics applied to real-world habits.
6. Stridekick, "Stridekick — Group Step Challenges With Wearable Verification." [Online]. Available: https://stridekick.com/. Reference for group challenges whose progress is validated from connected wearable data.
7. StepBet, "StepBet — Staked Step Challenges." [Online]. Available: https://www.stepbet.com/. Reference for commitment-driven challenge design; its staking model is deliberately excluded from the MVP for legal reasons.
8. Strava, "Strava — Clubs, Challenges, and Device-Verified Activity." [Online]. Available: https://www.strava.com/. Reference for sensor-verified achievement as a high-trust proof standard.
9. Duolingo, "Duolingo — Streaks, XP, and Leagues." [Online]. Available: https://www.duolingo.com/. Reference for streak psychology, league ladders, and quiz-gated progress in the progression design.
10. Reddit, "Reddit — Communities, Threaded Posts, and Voting." [Online]. Available: https://www.reddit.com/. Reference for the community and threaded-post model, and for the vote-based ranking that inspires the feed.
11. Discord, "Discord — Servers, Channels, Roles, and Community Chat." [Online]. Available: https://discord.com/. Reference for channel structure, role-gated privileges, real-time chat, and XP levels.
12. BeReal, "BeReal — Daily Ephemeral Authenticity." [Online]. Available: https://bere.al/. Reference for the twenty-four-hour ephemeral story mechanic used by the always-on content layer.
13. GitHub, "GitHub REST API Documentation." [Online]. Available: https://docs.github.com/rest. Interface contract used by the repository verification check for commit freshness and README presence.
14. International Organization for Standardization, ISO/IEC 25010:2011 — Systems and Software Quality Requirements and Evaluation (SQuaRE): System and Software Quality Models. Geneva: ISO, 2011. Model used to structure the quality attributes assessed by the non-functional tests.
15. Institute of Electrical and Electronics Engineers, IEEE Std 830-1998 — IEEE Recommended Practice for Software Requirements Specifications. New York: IEEE, 1998. Recommended practice that guided the structure and quality of the requirements specification.
16. OWASP Foundation, "OWASP Top 10:2021 — The Ten Most Critical Web Application Security Risks," 2021. [Online]. Available: https://owasp.org/www-project-top-ten/. Reference for the authentication, access-control, and input-validation checks in the security test plan.
17. European Union, "Regulation (EU) 2016/679 — General Data Protection Regulation (GDPR)," 2016. [Online]. Available: https://gdpr-info.eu/. Legal basis for the data export, erasure, and consent requirements in FR-1.4.
18. Government of India, "The Digital Personal Data Protection Act, 2023." New Delhi: Ministry of Electronics and Information Technology, 2023. Statutory basis for data-principal consent and data-fiduciary obligations in the Indian pilot deployment.
19. R. S. Pressman and B. R. Maxim, Software Engineering: A Practitioner's Approach, 9th ed. New York: McGraw-Hill, 2019. Reference for requirement engineering, process models, and testing terminology used throughout the report.
20. I. Sommerville, Software Engineering, 10th ed. Harlow: Pearson, 2016. Reference for software process, architectural design, and the layered test strategy adopted in this chapter.
21. B. W. Boehm, Software Engineering Economics. Englewood Cliffs: Prentice Hall, 1981. Reference for the COCOMO effort model and cost estimation principles applied in Chapter 2.
